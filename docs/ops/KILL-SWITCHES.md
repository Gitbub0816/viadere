# Kill switches and emergency controls (OPS-006)

**Status:** v2, 2026-10-28 (WP6). v1 (2026-10-27) listed what existed and fifteen gaps; WP6 closed G-1, G-3, G-5, G-6, G-7, G-8, G-9, G-10, G-12, G-13 and G-15
in code (section 2 says where each lives and which test proves it). G-2 (per-capability toggles) and G-14 (issuer trust list) were delivered by WP2/WP3 (E-18);
G-4 (vault sync) is the `VAULT_SYNC_ENABLED` flag; G-11 (origin mTLS) stays open and needs a platform decision (section 2, G-11).
OPS-006 asks for safe kill switches, credential revocation, business suspension, replay-cache enforcement, webhook pause, emergency messaging restrictions and
notification of affected parties. Everything below "Exists" works in the code today; "Needs real infrastructure" rows are marked. Tracked as risk R-034.

## 1. What exists

| # | Control | Scope | How to use it | Effect and limits |
|---|---|---|---|---|
| E-1 | **Suspend a business** | one business | Operator console `/operator/businesses/{id}` -> Suspend (reason required, passkey re-auth); reinstate with Reinstate | Next request is refused for its API keys and interactions; pending interactions are cancelled (`business.suspended` audited). Blunt: all capabilities stop at once |
| E-2 | **Throttle a business** | one business | Operator console -> throttle; also automatic (`abuse.auto_throttled`) from `ABUSE_COMPLAINT_RATE`, `ABUSE_OPTOUT_RATE`, `ABUSE_MIN_SAMPLE`, `ABUSE_WINDOW_DAYS` | Daily quota and API rate x `ABUSE_THROTTLE_FACTOR` (0.25 default) |
| E-3 | **Priority ceiling** | one business | Operator console -> ceiling (downward only: low, normal, high) | Restricts only; never raises |
| E-4 | **Revoke an API key** | one key, or all keys of a business | Business dashboard `/dashboard/api-keys` -> Revoke (`apikey.revoked`); **operator** `/operator/businesses/{id}` -> Revoke key / Revoke all keys (`apikey.revoked_by_operator`, G-3) | Immediate for that key. The operator action does **not** suspend the business; the organization is mailed and creates new keys |
| E-5 | **Delete / rotate a webhook endpoint** | one endpoint | Dashboard `/dashboard/webhooks` -> delete or rotate (`webhook.deleted`, `webhook.rotated`); `API: DELETE /v1/business/webhooks/{id}`, `POST .../rotate-secret` | Rotation keeps the previous secret for an overlap window. **Pause** per endpoint (`POST /v1/business/webhooks/{id}/pause`, console) and per business or globally by an operator (G-5, section 2) |
| E-6 | **Replay a webhook delivery** | one delivery | Dashboard `/dashboard/webhooks/deliveries/{id}` -> Replay | A recovery tool, not a kill switch |
| E-7 | **Revoke a device / session** | one consumer device; whole account | User: `DELETE /v1/devices/{id}`; automatic on expiry, on recovery activation and on refresh-token reuse detection; **operator** `/operator/consumers` -> Freeze account (G-7) | A bearer token alone cannot enroll a device. A freeze ends every session and device and blocks sign-in, approvals and recovery until lifted |
| E-8 | **Cancel a recovery / device replacement** | one account | User: `/v1/recovery/{id}/cancel`, `/v1/devices/{id}/cancel-replacement` from a trusted device | Defense against account takeover |
| E-9 | **Replay protection** | all signed requests | Always on: `DatabaseReplayGuard` (`replay_nonces`), 300 s skew, single-use challenges | Automatic; there is no flush or tighten control (see G-9) |
| E-10 | **Rate limits** | per namespace | Always on, database store, fail closed for security-critical namespaces; Cloudflare edge rules in `Infra/terraform/cloudflare.tf` | Abuse thresholds change at runtime within bounds (G-12); per-namespace limits still change with a deploy |
| E-11 | **Stop all background delivery** | whole fleet | Set `RUN_BACKGROUND_JOBS=false` (a plain `[env]` value, not a secret): change it in `fly.*.toml` and redeploy, or `fly machine update <id> --env RUN_BACKGROUND_JOBS=false` on each machine | Halts outbound SMS/RCS, webhooks, pass pushes, expiry sweeps, **and** purge/limiter cleanup. Inbound still accepted and queued |
| E-12 | **Disable a channel/feature by configuration** | whole fleet | Unset RCS values (SMS only); unset Wallet values (pass endpoints answer 501); `FEATURE_APPLE_MESSAGES_FOR_BUSINESS=false`; `OTP_ALLOWED_COUNTRIES=` narrowing; `APP_ATTEST_MODE` | Requires a config change and rolling restart (minutes). Unsetting Twilio is refused by staging/production config validation |
| E-13 | **Edge block** | by path/host/IP/country | Cloudflare: add a WAF custom rule (block or challenge) via dashboard or Terraform; "Under Attack" mode | The fastest global switch we have (seconds), independent of the app. Coarse: path/IP based |
| E-14 | **Stop the origin** | whole API | `fly scale count 0 --app viadere-server` (or `fly machine stop`) | Total outage; last resort. Neon compute can be suspended separately |
| E-15 | **Reject unsafe configuration** | startup | `ENVIRONMENT` required, secrets mandatory and distinct, `seed` refused in staging/production | Prevents misconfiguration, not an incident control |
| E-16 | **Audit and dispute tooling** | forensic | `ViadereServer audit-head`, `audit-verify [--head file]`, `export-dispute --interaction <id>` | Detection and evidence, see RUNBOOKS.md |
| E-17 | **Operator enrollment** | operators | `ViadereServer create-operator` creates an operator enrollment link (audited `operator.created`) | Operators are the people who use E-1 to E-3; protect the console and review membership monthly |
| E-18 | **Stop Verify** (WP3) | whole fleet; per capability or business via WP2; Didit alone | `VERIFY_ENABLED` unset/`false` (plain `[env]` value, redeploy): every Verify route answers `404` and any request in flight ends `not_verified` with nothing disclosed; provider sessions are still purged. Finer: operator console capability switches for `age.minimum`, `identity.*` (global or one business, immediate within 5 s) deny creation and disclosure; revoking an API key or an entitlement also stops requests already in flight. **Didit alone: `DIDIT_NEW_SESSIONS_ENABLED=false`** (plain `[env]` value, redeploy): no new document session starts and the app stops offering the document method, but the purge client stays (it needs only `DIDIT_API_KEY`), so finished and abandoned sessions are still deleted at Didit. **Do not remove `DIDIT_API_KEY` to stop Didit**: that also stops every erasure (the purge client then does not exist) and is not a switch | The Wallet method alone is stopped by removing `WALLET_MERCHANT_ID`. Rotate `DIDIT_WEBHOOK_SECRET` if the webhook secret leaks (the previous one overlaps 24 h). Purge failures never give up (exponential backoff 30 s to 24 h, `purge_next_at`); watch `viadere_verify_provider_purge_overdue` (alert when above 0 for 10 minutes) and `viadere_verify_provider_purge_pending`; a purge that cannot run (key revoked, long outage) is bounded only by **Didit's own data-retention setting, which must be configured to the shortest window the account allows** (RB-9) |

| E-19 | **Stop Brand Kits** (Phase 2) | whole platform or one business | Operator console `/operator/brand` -> Brand Kits kill switch (reason, passkey re-auth; `platform.switch_set` with flag `brand_kits`); a single kit or image: Take down on the same page (`brandkit.kit_taken_down`, `brandkit.asset_taken_down`) | Within 5 s no brand manifest and no brand image is served for the scope; apps render Viadere's neutral style at once and nothing else changes (approvals, sign-in and messaging never depend on branding). Purge the asset URLs in Cloudflare after an emergency takedown (cached copies are immutable). Configuration-level: unset the brand-manifest key (Brand Kits off) |

## 2. The gaps of v1 and how WP6 closed them

Every switch below needs a **fresh passkey assertion** (operators re-authenticate every 5 minutes for mutations), a **recorded reason** (8 to 300 characters), is
**audited with the operator as actor** (`platform.switch_set`, `platform.switch_cleared`) and appears on `/operator/switches`. Switches live in the table
`platform_flags` (one row per flag and scope: `global` or a business id) and are read through a 5-second cache, so a change takes effect on the instance that made it at
once and on every other instance within 5 seconds, **without a redeploy**. Tests: `WP6KillSwitchTests`, `WP6EdgeTests`, `WP6KeyTests`, `WP6RotationTests`, `WP6RetentionTests`.

| ID | Control | How to use it | Effect and limits | Status |
|---|---|---|---|---|
| G-1 | **Maintenance / read-only mode** | `/operator/switches` -> Maintenance: on with a static message (up to 200 characters) | Every request that is not `GET`/`HEAD`/`OPTIONS` answers `503` with the message and `Retry-After: 60`. Exempt: `/healthz`, `/readyz`, `/operator/*` (so it can be lifted), `/metrics` and the SMS/RCS provider callbacks `/v1/providers/*` (an opt-out must never be lost). Reads, including the business API, keep working | Closed (`MaintenanceMiddleware`) |
| G-2 | Per-capability toggles | `/operator/policy` -> capability switch (global or one business) | Immediate within 5 s; fail closed for `approve` and `verify` | Closed in WP2 (E-18) |
| G-3 | **Operator key revocation without suspension** | `/operator/businesses/{id}` -> Revoke key / Revoke all keys (`all`, `live`, `test`) | Keys stop on the next request; the business stays active, can sign in and create new keys; owners and admins are mailed (no secret in the mail); audited `apikey.revoked_by_operator` | Closed (`APIKeyLifecycle.revoke/revokeAll`) |
| G-4 | Vault-sync kill switch | `VAULT_SYNC_ENABLED=false` (config) | The vault routes answer 404; clients keep working locally | Closed by the existing flag (config change, not runtime) |
| G-5 | **Webhook pause** | Per endpoint: console or `POST /v1/business/webhooks/{id}/pause` / `resume`. Per business or global: `/operator/switches` -> Webhooks | Queued deliveries stay queued (neither sent nor dead-lettered) and go out after a resume; the retention job still expires them with the webhook-delivery period, so a pause cannot keep message text for ever; the business sees a banner | Closed (`WebhookService.setPaused`, `PlatformFlags.webhooksPaused`) |
| G-6 | **Emergency messaging restriction** | `/operator/switches` -> Messaging restriction: channels (`sms`, `rcs`, `push`), `block` or `clamp` (1 to 600 per minute), global or one business | Enforced in the SMS/RCS channel worker, the push for interactions, conversation push notices and the SMS thread replies. A blocked interaction text is cancelled and audited (`channel.restricted`); a clamp defers the rest to the next window. **Security-purpose traffic (sign-in and payment approvals) is never restricted** (`MessagingGate`); stop those with a capability switch or suspension | Closed (`MessagingGate` wired into `ChannelRouter`, `InteractionService.push`, `ConversationService`, `GatewayService`) |
| G-7 | **Consumer freeze + session revoke with a notice** | `/operator/consumers` -> Freeze account (id, reason) / Unfreeze | Status `frozen`: every session, device and token is revoked, sign-in, approvals, recovery and refresh are refused (every route already requires `active`). The person gets a generic in-app notice and push (sent **first**, because their devices are revoked next); the internal reason is not shown to them. Unfreezing restores the status only: the person signs in again with their passkey and re-enrolls through the normal flows with their cool-downs | Closed (`ConsumerFreeze`) |
| G-8 | **Key-rotation tooling** | `docs/ops/KEY-ROTATION.md`: `DATA_ENCRYPTION_KEY_ID` + `DATA_ENCRYPTION_KEYS_PREVIOUS`, `ViadereServer rotate-data-key` / `verify-data-key [--require-current]`; `SERVER_PEPPER_ID`; `AUDIT_CHAIN_KEY_EPOCH`; `CONNECT_LINK_SIGNING_KEY_ID` | Multi-key read with one write key; re-encryption is idempotent and safe while serving; the audit chain stays verifiable across epochs (the epoch is inside the MAC and may never decrease); issued connect links stay valid until they expire | Closed for the data key, audit chain and connect links. **Limit:** the pepper is versioned but existing peppered *lookup* hashes (`hmacHex`: phone, e-mail, recovery) change with it and have no automatic re-hash (KEY-ROTATION.md section 3); new hashes use `versionedHex` |
| G-9 | **Operator notices to affected parties** | `/operator/notices` or `/operator/businesses/{id}` -> Notify: scope `business`, `all_businesses`, `consumers_of_business`, `all_consumers`; severity | Business notices go by e-mail to owners, administrators and security contacts; consumer notices appear in the app's security notices with a generic push. Created instantly, delivered in batches of 200 by the job (never inline); business users see them under Support > Notices. `replay_nonces` flush is intentionally not offered | Closed (`OperatorNotices`) |
| G-10 | **Enforce `EDGE_TOKEN`** | Fly secrets `EDGE_TOKEN` (required in staging and production; `EDGE_TOKEN_PREVIOUS` during rotation) | Any request without a constant-time-equal `X-Viadere-Edge-Token` gets `421` before routing, authentication or database access. Health checks (`/healthz`, `/readyz`, GET/HEAD) are exempt **only** from Fly's private network (peer in `fdaa::/16`, `172.16.0.0/12`, `10.0.0.0/8`, loopback) **and** with no proxy header (`X-Forwarded-For`, `Forwarded`, `Fly-Client-IP`, `CF-*`, `X-Real-IP`, `True-Client-IP`, `Via`). Cloudflare and Fly's proxy always add one, so a request through either never qualifies. Startup refuses to boot without it in staging and production | Closed (`EdgeLockMiddleware`; Infra/fly/README.md step 6) |
| G-11 | Authenticated Origin Pulls verified at the origin | Not in code: either a raw-TCP Fly service with app-terminated TLS and Cloudflare's origin-pull CA as the only trust root, or Cloudflare Tunnel (`cloudflared`) with no public origin | Layers 1 (`EDGE_TOKEN`) and 3 (alert on non-`api.viadere.com` hosts) are in force; the certificate layer needs a platform decision | **Open. Needs real infrastructure** (Infra/fly/README.md) |
| G-12 | **Runtime abuse thresholds** | `/operator/switches` -> Abuse thresholds | Complaint rate 0.5-20 %, opt-out rate 2-50 %, minimum sample 5-1000, window 1-30 days, throttle factor 0.05-1.0: a value outside its bound is refused, so the checks can be tightened or relaxed but never switched off; env values remain the defaults | Closed (`AbuseOverride`) |
| G-13 | **Protected metrics without PII** | `METRICS_TOKEN` (bearer) on `GET /metrics`, or a separate internal listener `METRICS_PORT` | Counters and gauges with a fixed vocabulary of names and bounded labels: requests by class, rejections (edge, API key, IP, mTLS), switches, limiter fail-closed, dead-letter count, audit-head export age, assurance failures, outstanding Didit deletions (`viadere_verify_provider_purge_*`). No identifiers, no business names, no addresses. Without a token the route answers 404 | Closed (`MetricsRegistry`). Alert rules in a monitoring tool need real infrastructure |
| G-14 | Issuer / Wallet-ID trust list | IACA allow-list with enable/disable | Immediate | Closed in WP3 (E-18) |
| P3-L | **Hosted Loops** (plan 5.5) | `/operator/switches` -> Loops: `loops` (platform); `/operator/loops` -> per business ("Pause all Loops of this business", `loop_switches`) and per Loop (publication `suspended`, `revoked`, `retired`) | No new instance (`409`); existing instances are served with `paused: true` and every action is refused; the available list is empty; core messaging, approvals and verification are unaffected; revoke also cancels open instances. Every change needs a reason and is audited | Closed (`LoopRuntimeService`, `LoopPublicationService`; tests `LoopReviewPipelineTests`) |
| G-15 | **Sign-up stop switches** | `/operator/switches` -> Sign-ups: `signup.consumer`, `signup.business`, `invite.dashboard` | New consumer registration, new business sign-up, and dashboard invitations (creating and accepting) answer `503`; existing accounts keep signing in | Closed (`SignupGateMiddleware`) |

Fail-open and fail-closed, stated plainly: if the `platform_flags` table cannot be read the switches read as "not set" (every switch restricts something that needs the same
database anyway); the **edge lock** has no database dependency and fails closed; the limiter and capability switches keep their documented behaviour.

## 3. Interim operating procedure until the gaps close

1. Credential leak: operator revokes the key(s) (G-3), notifies the business (G-9); suspend (E-1) only if the business itself is the threat.
2. Business-scoped abuse: restrict messaging (G-6) or throttle (E-2), then suspend (E-1); pause webhooks (G-5) for a takeover suspicion.
3. Consumer compromise or coercion: freeze the account (G-7); the notice explains it without the internal reason.
4. Data-integrity incident: maintenance mode (G-1), then the audit-head comparison in RUNBOOKS.md.
5. Sign-up abuse: stop sign-ups (G-15), then an edge rule (E-13).
6. Fleet-scoped or capability-scoped problem: capability switch (E-18/G-2) or an edge rule (E-13), then config change (E-12), then E-11.
7. Everything above is recorded in the incident record; the switch page lists what is currently on, who set it and why.
